Stage 1: Face Feature Extraction File: src/models_improved.py — Class: FaceFeatureExtractor

What Happens

Each face image goes through FaceNet (InceptionResnetV1) pretrained on VGGFace2 (3.3 million face images of 9,131 identities).

Raw Image (any size) → Resize to 224×224 → Normalize → FaceNet → 512-d vector → L2 normalize

Technical Details

  1. Image is resized to 224 × 224 pixels and converted to RGB
  2. Pixel values are normalized using ImageNet statistics: mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]
  3. FaceNet's InceptionResnetV1 processes it through ~20M parameters
  4. Output is a 512-dimensional embedding vector
  5. L2 normalization ensures ||emb|| = 1 — maps all embeddings onto a unit hypersphere

Why FaceNet?

  • Trained specifically for face verification (not general image classification)
  • VGGFace2 gives it knowledge of facial identity across age, pose, and lighting
  • The 512-d embedding captures identity-discriminative features (face shape, eye distance, nose bridge, jawline)
FaceNet is frozen (no gradient updates). It acts purely as a fixed feature extractor. All the "learning" happens in Stage 2 — the quantum-inspired projection.
Stage 2: Quantum-Inspired Cross-Attention Projection File: src/models_improved.py — Class: QuantumInspiredCrossAttention (~660K trainable params)

This is the most novel and important part of the architecture. It transforms 512-d face embeddings into 8 quantum angle parameters that will be used to prepare quantum states.

Step 2.1: Relation Conditioning

# One-hot relation vector: [FD, FS, MD, MS]
rel_bias = rel_embed(rels)   # (B, 4) → Linear(4,64) → GELU → Linear(64,512) → (B, 512)
e1 = emb1 + rel_bias         # (B, 512) — Person A + relation context
e2 = emb2 + rel_bias         # (B, 512) — Person B + relation context

The 4-dimensional one-hot relation vector is projected to 512-d and added to both embeddings. This tells the model: "evaluate these faces under the hypothesis that they are Father-Daughter" (or whichever relation).

A father-son pair might share jaw structure while a mother-daughter pair might share eye shape. Relation conditioning lets the model learn different similarity patterns for different relationship types.

Step 2.2: Multi-Head Cross-Attention (8 heads × 64-d)

# Person 1 attends to Person 2 — "What in B is relevant to A?"
attn_out1 = CrossAttention(query=e1, key=e2, value=e2)   # (B, 512)

# Person 2 attends to Person 1 — "What in A is relevant to B?"
attn_out2 = CrossAttention(query=e2, key=e1, value=e1)   # (B, 512)

# Residual connection + Layer Normalization
h1 = LayerNorm(e1 + attn_out1)   # Preserves original information
h2 = LayerNorm(e2 + attn_out2)

Each person's embedding is enriched by "looking at" the other person's features. The attention mechanism learns which aspects of Person A's face to compare with which aspects of Person B's face.

Step 2.3: MLP Projection to Quantum Angles

# Compress 512-d representation to 8 quantum rotation angles
z = Linear(512, 256) → GELU → Dropout(0.3)
  → Linear(256, 128) → GELU → Dropout(0.3)
  → Linear(128, 8) → LayerNorm

# Scale to valid quantum rotation range
z = tanh(z) × π       # Output: z ∈ [-π, π]⁸

Step 2.4: Quantum-Inspired Interference (Novel Contribution)

# Learnable phase matrix: 8×8 parameters
interference1 = cos(z₁ @ phase_matrix)   # (B, 8) — cross-qubit coupling
interference2 = cos(z₂ @ phase_matrix)   # (B, 8)

# Modulate angles with interference pattern
z₁ = z₁ × interference1                 # Element-wise multiplication
z₂ = z₂ × interference2
In a real quantum computer, entanglement creates correlations between qubit measurements. Here, the learnable phase_matrix creates similar correlations — changing one angle affects the effective value of all others through the cosine coupling.

Stage 3: Quantum SWAP Test Fidelity File: src/quantum_core.py — The Core Physics

3.1: What is a SWAP Test?

The SWAP test is a quantum algorithm that measures how similar two quantum states are. Given states |ψ₁⟩ and |ψ₂⟩:

Fidelity = |⟨ψ₁|ψ₂⟩|²

This equals 1 when states are identical and 0 when states are orthogonal (completely different).

3.2: The Quantum Circuit (17 Qubits)

The full circuit uses 1 ancilla qubit + 8 register-1 qubits + 8 register-2 qubits = 17 qubits total:

Ancilla (q₀): ──H──●──●──●──●──●──●──●──●──H──M── │ │ │ │ │ │ │ │ Register 1: Ry(z₁)─Rz(e₁)─CX────────────────× × × × × × × × (Person A) │ │ │ │ │ │ │ │ Register 2: Ry(z₂)─Rz(e₂)─CX────────────────× × × × × × × × (Person B) Legend: H = Hadamard | Ry = Y-rotation | Rz = Z-rotation | CX = CNOT | × = CSWAP | M = Measure

Circuit Steps:

  1. Hadamard on Ancilla: Put ancilla in superposition |+⟩ = (|0⟩ + |1⟩)/√2
  2. State Preparation (for each register):
    • Ry(zᵢ) angle encoding on each qubit (encodes face similarity information)
    • CNOT chain connecting adjacent qubits (creates entanglement)
    • Rz(ent_paramᵢ) learnable phase rotations (adds learned structure)
  3. Controlled-SWAP gates: For each qubit pair, CSWAP controlled by ancilla
  4. Hadamard on Ancilla: Interfere the two branches
  5. Measure Ancilla: P(ancilla = 0) = (1 + |⟨ψ₁|ψ₂⟩|²) / 2
Fidelity = 2 × P(ancilla measures 0) − 1

3.3: Entangled State Preparation

For each register, the quantum state is prepared via 3 layers:

Layer Gate Purpose Parameters
Layer 1 Ry(zᵢ) on each qubit Angle encoding — embeds face features as rotation angles 8 angles from Stage 2 (data-dependent)
Layer 2 CNOT chain: q₀→q₁→q₂→...→q₇ Creates entanglement — correlations between qubits None (fixed structure)
Layer 3 Rz(ent_paramᵢ) on each qubit Learnable phase shifts — adds structure to quantum state 8 learnable params per register (16 total)
Register 1 uses ent_params1 and Register 2 uses ent_params2 — these are different learnable parameters. This means the two registers undergo different transformations, making the fidelity NOT equivalent to the simple product-state cosine formula. This is what makes the "entangled" encoding more expressive than the "product" baseline.

3.4: Two Computation Modes

Mode A: PyTorch (Training)

Fully differentiable statevector simulation in pure PyTorch. Gradients flow through Ry, CNOT, and Rz gates.

state = |0⟩⊗8  (256-d vector)
for i in 0..7:
  state = Ry(z[i]) @ state
for i in 0..6:
  state = CNOT(i,i+1) @ state
for i in 0..7:
  state = Rz(ent[i]) @ state

fidelity = |⟨state1|state2⟩|²

Mode B: Qiskit (Verification)

Actual quantum circuit simulation on Qiskit AerSimulator with 1024 shots. Used to verify PyTorch matches "real" quantum.

circuit = build_circuit(
    n_qubits=8,
    z1, z2,
    ent_params1,
    ent_params2
)
job = AerSimulator().run(
    circuit, shots=1024
)
fidelity = 2*P(0) - 1

3.5: Product-State Analytical Shortcut (Ablation Only)

When encoding_mode="product" (no entanglement, no Rz), fidelity has a closed-form:

F = ∏ᵢ₌₁⁸ cos²((z₁ᵢ − z₂ᵢ) / 2)

This is used only for ablation experiments to demonstrate that the entangled version with learnable Rz parameters outperforms the product-state baseline.

Stage 4: Ensemble Inference File: src/models_improved.py — Class: EnsembleKinshipClassifier

The deployed model is an ensemble of 5 independently trained models (one per cross-validation fold).

class EnsembleKinshipClassifier:
    def forward(self, emb1, emb2, rels):
        predictions = []
        for model in self.models:           # 5 sub-models
            pred = model(emb1, emb2, rels)  # Each gives fidelity ∈ [0,1]
            predictions.append(pred)
        return mean(predictions)            # Soft voting: average fidelity
Each fold model sees slightly different training data, so they learn slightly different decision boundaries. Averaging reduces variance and improves generalization — from ~67% single-model to ~70%+ ensemble on unseen data.
Training Methodology Loss Function, Optimizer, and Cross-Validation Strategy

Loss Function (3 Components)

1. Binary Cross-Entropy (Main Loss)

loss = BCE(predicted_fidelity, smoothed_label)
# Labels smoothed: 1 → 0.95, 0 → 0.05 (prevents overconfidence)

2. Quantum Discrimination Loss (Weight: 0.3)

mean_kin    = mean(fidelity[kin_pairs])
mean_nonkin = mean(fidelity[nonkin_pairs])
loss += max(0, 0.2 − (mean_kin − mean_nonkin))
# Forces a margin of at least 0.2 between kin and non-kin average fidelities

3. Physics-Informed Regularization (Weight: 0.1)

# Keep Rz angles in reasonable range
angle_penalty = relu(|ent_params| − 0.9π)

# Encourage moderate difference between register params
ent_reg = |mean_diff(ent_params1, ent_params2) − 0.5|

# Encourage orthogonal relation embeddings
orthogonality_loss = ‖R × Rᵀ − I‖

What Makes This Architecture "Quantum"? Classical vs. Quantum-Inspired Components
Component Classical Equivalent Quantum Inspiration
FaceNet embeddings Standard face features None (purely classical)
Cross-Attention + MLP Feature transformation Output represents quantum rotation angles
Phase Matrix interference No direct analogue Mimics quantum interference between qubits
Ry + CNOT + Rz encoding Feature concatenation Creates entangled quantum states from face features
SWAP Test fidelity Cosine similarity Quantum state overlap — different similarity metric
Ensemble averaging Standard bagging None (classical ensemble)
Instead of computing cosine_similarity(face_A, face_B) like standard approaches, this model: (1) Encodes faces as quantum states via learned rotations, (2) Measures similarity as quantum fidelity (state overlap), (3) The entangled encoding with learnable Rz parameters creates a non-linear, learnable similarity metric that can capture complex kinship patterns beyond what cosine similarity can.
